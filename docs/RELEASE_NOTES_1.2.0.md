# XML Agent 1.2.0 发布说明

这一版的主题是**技能（Skills）**：把"写作规范、流程约定"这类长文档从系统提示词里拿出来，
做成工作区里可读、可改的 Markdown 指令，模型按需 `read` 进来照着做。同时内置第一份技能
——《男频网文写作》，并实测跑通了"连续写 10 章"。

协议、插件 API、动作清单均无破坏性变更（`apiVersion` 仍为 `1`）。**没有技能时，首轮提示词
与 1.1.1 逐字节一致**（有单测钉住），既有任务行为不受影响。

## 一、新增：技能系统

技能 = 一份自包含的 Markdown 指令文档。它不注册新动作，也不常驻提示词，只在首轮提示词里
留一行"名称 + 相对路径 + 一句话用途"，模型判断需要时自己 `read` 全文。

### 三个来源，同名按优先级覆盖

| 来源        | 位置                                  | 用途                 |
| ----------- | ------------------------------------- | -------------------- |
| `builtin`   | `<安装目录>/skills/<name>/SKILL.md`   | 随安装包分发，只读   |
| `user`      | `~/.xml-agent/skills/<name>.md`       | 跨工作区共享，可改   |
| `workspace` | `<workspace>/.agent/skills/<name>.md` | 随项目走，可改、可删 |

同名技能三份**都会列出来**，用 `active` 标出哪份生效、`shadowedBy` 标出被谁盖住。早期版本
按名字去重，结果"装到工作区后内置那份整个消失、`builtin:xxx` 变 404、再装一次也失败"——
这个 bug 被单测抓出来后才改成现在的样子。

### Skills 面板

右上角 **Skills** 打开，左侧按来源分组，右侧是文档全文：

- **读**：Markdown 渲染，附路径、可读路径、大小、更新时间；
- **改**：点 **Edit** 直接就地编辑，`Ctrl/⌘+S` 保存，整篇覆盖；改动未保存时按钮区显示 `unsaved`，
  期间 Reload 会禁用，避免把草稿冲掉；
- **内置技能只读**：点 **Copy & edit** 会先复制一份到工作区，之后改的是那份副本。`app.asar` 里的
  文件改了下次升级也会被覆盖，不如一开始就改可控的那份；
- **启用/禁用**：只影响是否进首轮提示词，文件不动；状态落在 `<storeRoot>/skills.json`；
- **安装到工作区**：`read` 被沙箱限制在工作区内，内置与用户级技能不安装模型读不到。列表里
  `Readable by agent` 为空就是在提示这件事。

写入侧做了三处防护：只允许写 `user` / `workspace` 两层；写回位置必须落在该来源自己的根目录内
（拦住符号链接指到目录外）；单篇上限 1 MB（HTTP 侧受 100 KB 请求体限制，技能文档本来就该精简）。

### 接口

```
GET    /api/skills                列表（来源 / 启用 / 可读路径 / 是否可编辑）
GET    /api/skills/:id            读全文
PUT    /api/skills/:id            保存（内置回 403）
POST   /api/skills/:id/enabled    启用 / 禁用
POST   /api/skills/:id/install    复制到工作区
DELETE /api/skills/:id            从工作区移除
```

## 二、内置技能：男频网文写作

`skills/novel-writing/SKILL.md`，随安装包分发。核心是把"好看的网文"拆成可执行、可自检的规则：

- **八条铁律**：开篇必须有事件、前三章必须完成"打脸/反杀"、每章有小目标 + 结果 + 章末钩子、
  设定随冲突出现不说说明书、对话占比不低于 30% 等；
- **黄金三章**与**单章八段式**骨架（150/300/400/350/200/400/150/100 字的段落配额）；
- **可数代理指标**：40 段 ≈ 2000 字、每 5 段至少 2 段有人开口说话——让"够不够"这件事有客观刻度；
- **自检五问**与禁用词表。

**实测**：用 Qwen 按这个技能连写 10 章，14 步、约 15 分钟、19,679 字、12 次 `write` 全部成功。
暴露的短板也写进了技能文档：3 章低于 1800 字、对话占比只有 9~20%、偶发禁用词。

## 三、配套：章节自检脚本

`scripts/check-novel.js` 按可机检项给单章打分（字数、段数、对话占比、禁用词、章末钩子），
写完自己先过一遍，比通读一遍再改省事。

## 四、小修

- `exec` 动作的说明补上引号规则：`command` 是 XML 属性，里面写双引号会截断标签，
  要么用单引号，要么写 `&quot;`。模型此前在 `python -c "..."` 上踩过这个坑（exit 2）。
- `skills/README.md`：怎么自己写一份技能、front matter 有哪些字段、目录该放哪。

## 五、升级说明

- 直接覆盖安装即可。1.1.1 的工作区、会话、插件配置、API Key 都沿用原位置。
- 首次打开 Skills 面板只会看到内置的写作技能，把需要的点 **Install to workspace** 之后模型才读得到。
- 想改内置技能的规则：**Copy & edit**，改的是工作区副本，将来升级不会被覆盖。
