# XML Agent 1.3.0 发布说明

这一版的主题是**把"一次能做完的事"变多**：改代码不用整篇重写（新增 `edit` 动作）、
上下文快满时能把记忆带到新会话接着做（记忆转移 + 上下文预算）、Web 端能真正把图片发进去了。
顺带把界面做成中英双语，并对提示词做了一次瘦身。

协议、插件 API 均无破坏性变更（`apiVersion` 仍为 `1`）。动作表新增一个 `edit`，
内置动作保留名同步更新——**已有插件若自己注册了名为 `edit` 的动作，会在这个版本冲突**，
请改名（`plugins/sdk.js` 的 `RESERVED_ACTION_NAMES` 会直接拒绝注册并报出冲突名）。

## 一、新增动作：edit（局部修改）

`write` 是整篇覆盖，改一行也要把几千行重新发一遍：既费 token，也容易在重发时把没注意到的
地方改坏。`edit` 用"原文片段 → 新片段"的锚点替换，只发要动的那几行：

```xml
<edit path="src/config.js">
    <old><![CDATA[const port = 3000;]]></old>
    <new><![CDATA[const port = process.env.PORT || 3000;]]></new>
</edit>
```

- 一次可带多组 `<change><old/><new/></change>`（上限 20 组），按顺序替换；
- `<new>` 留空即删除；`all="true"` 替换全部命中；
- **两档匹配**：先精确匹配；失败再按"忽略行首缩进与行尾空白"匹配，命中后按逐行缩进差把
  `<new>` 对齐回原缩进，并在结果里标注 `matched: "loose"` + 提示；
- **多义直接拒绝**，不猜：同样的片段出现多处时报出全部行号，要求补上下文或加 `all="true"`；
  `all="true"` 遇上宽松匹配也拒绝（那等于"猜着改一遍"）；
- 任一 `<change>` 失败则整次不落盘（临时文件 + rename），不会留下改了一半的文件；
- 返回体带 `diff`（只列替换行，40 行 / 2000 字符截断）和 `hint`，模型能自己核对改对没有。

CDATA 里可以放 `<`（脚本、JSX、比较运算）不必转义；`old` 含 `]]>` 这种极端情况无法用 CDATA
包裹，属 XML 限制，遇上报错会明确说明。

单测 34 项覆盖两种写法、CDATA 与实体解码差异、歧义行号、`all`、删除、CRLF、宽松匹配两个方向、
原子性、二进制/目录/越界路径、diff 截断。

## 二、上下文预算与会话记忆转移

### 按真实 prompt 估算上下文

原来的百分比是拿"字符数 × 系数"粗估，跟实际发给模型的 prompt 差得远（系统提示、清单、
历史结果都会被漏算）。现在每轮用**真实的 `getRuntimeOkPrompt` 跑一遍**再计数：首轮按系统提示

- task + 工作区清单算，后续按实际回包算，模型回复按 `provider.response.length` 累加，图片按每张
  1200 token 近似。

会话信息条常驻显示 `上下文 N% · 转移会话 ▾`，80% 提醒、92% 危险（可配）。

### 四种转移模式

记忆分两层：`output` / `task` 存的**记录**只给界面回看，模型下一句看不到；真正的记忆是
`conversationId` 指向的 provider 对话线程。转移时按需选：

| 模式      | 搬什么               | 模型记得历史 | 界面能看到历史 | 适用                     |
| --------- | -------------------- | ------------ | -------------- | ------------------------ |
| `full`    | 记录 + 线程          | ✅           | ✅             | 换会话接着做，上下文宽裕 |
| `records` | 只搬记录             | 靠摘要       | ✅             | 想留档，但要干净对话     |
| `link`    | 只接续线程           | ✅           | ❌ 一行说明    | 上下文重要，界面不想变长 |
| `digest`  | 只搬 task + 一页摘要 | 靠摘要       | ❌ 一行说明    | 上下文满了换会话（推荐） |

上下文快满时用 `digest`：旧记录正是塞满窗口的东西，一并搬过去只会让界面再长一遍。
Web 端横幅的「转移并新开」走这个模式；会话信息条的下拉提供 `digest` / `records` 两项，
**不必等到 80% 才能用**——想中途换个干净会话随时可以。

### 压缩与摘要

搬记录时默认先压缩（`compress`）：真实会话里体积几乎全花在对"接着做"没帮助的地方——
每条记录的 `event` 是 `content` 的原始副本（实测比 `content` 还大 1~2 倍），
外加几千条 `Agent step 42` 过程噪声。

| 档位     | 做什么                                                      | 实测（3.7MB 会话） |
| -------- | ----------------------------------------------------------- | ------------------ |
| `off`    | 原样搬                                                      | 0%                 |
| `auto`   | 不超预算不动手，超了先 `light`，仍超再 `strong`             | 省 87%             |
| `light`  | 去 `event` 副本 + 截断超长单条（头 60%/尾 20%）+ 折叠噪声   | 省 70~87%          |
| `strong` | `light` + 合并连续重复 + 按字符预算省略中段（留开头与结尾） | 省 80~90%          |

模型拿不到线程时（`digest` / `records`，或源会话压根没有 `conversationId`），插件把流水账压成
**一页 markdown** 落到工作区 `.xml-agent-memory/<to>.md`，并在新会话的 `task` 末尾写明
"开工前先 read 这个文件"。`digest` 模式拒绝 `digest=off`；摘要写不进工作区就整体失败，
不会留一个只有 task 的空会话。

### 修掉的三个 bug

1. **转移后回老会话报「会话不存在」**：`SessionManager.absorbRecord()` 先按构造函数生成的
   随机 UUID 入表、后 `restore()` 改 id，导致内存表的 key 与 `session.id` 不一致——侧栏能看到，
   `GET /api/sessions/:id` 却 404。改为先 restore 再入表。
   _测试盲区_：原有测试用假管理器、按 `payload.info.id` 入表，正好绕开这条路径；
   新增 `test/unit/test-session-absorb.js` 用真实管理器覆盖。
2. **转移后输入框是空的**：接手任务写进了 `task`，但前端按 `outputLength > 0` 判断"跑过了"，
   于是不回填。改为识别转移备注。
3. **回填后立刻被清空**：前端连 SSE 时服务端会重放 `finished`，回调里无条件清空输入框，
   造成了"刚填好就消失"。改为只在本次运行真的产出过内容（`runCount > 0`）时才清。

## 三、Web 端附带图片（识图）

修掉一个让整条链路完全失效的问题：`onFilesSelected` 里先 `event.target.value = ""` 再读
`files.length`，而 `input.files` 是**活的** FileList——清 value 就把它掏空了，于是选完文件毫无反应。

- 三种添加方式：点按钮、`Ctrl+V` 粘贴截图、拖文件进输入区；
- 本地预校验：单次 8 张、单张 20MB、png/jpg/jpeg/webp/gif/bmp，超限直接说明哪张被跳过，
  不会先把 21MB 传完再报错；
- 附件条显示缩略图 + 原始文件名；存盘加时间戳后缀防重名，界面显示时去掉；
- 图片按会话暂存，切走再切回来还在；发送后清空，不重复上传；
- 回读走 `GET /api/uploads/:name?workspace=...`，只允许 `uploads/` 下一级、扩展名白名单、
  路径包含校验。

顶层的 `uploads/` 不进工作区清单（避免白占提示词预算），记忆转移也不搬图片——它是一次性的
运行时状态。

## 四、界面中英双语

右上角一键切换 English / 中文，默认英文。覆盖 Web 与桌面端（同一套 SFC）。文案集中在
`webui/frontend/src/services/i18n.js`，`<html lang>` 跟着变。

## 五、提示词瘦身

网页版平台的提示词不是真正的 system 消息，而是一条普通用户消息。原文开头"你是一个运行在
Node.js Runtime 上的工程型 AI Agent"加几十条"必须/不允许"，在平台风控分类器里就是典型的
角色劫持 / 脚本注入模板；再叠加首条消息 6.5k 字符、每轮重复动作示例、外发工作区绝对路径，
整体像脚本批量灌入。

- 系统提示词 **4676 → 1484 字符**，改第一人称陈述任务，删掉重复的 XML 示例段与大段修辞性禁令；
- 每轮回包 **700 → 440 字符**量级，结果改紧凑 JSON，长字符串按 4000 字符、数组按 200 项截断并标注；
- 首轮不再发盘符路径，只给项目名；工作区清单加 8k 字符硬上限；
- 首轮总长 **6556 → 2524 字符**。

新增不变量测试钉住这些性质（不含盘符路径 / `127.0.0.1` / `CDP` / `Node.js Runtime`、
系统提示 < 2000 字符、回包 < 600 字符），以及"提示词里的每个示例都能被真解析器接受"。

> 提示词只能降低「内容特征」的命中率，消不掉封号风险。真正的主因是行为：轮次频率、
> 出错重试节奏、单账号同时挂几个会话。这部分不在提示词里，改提示词不会让自动化访问变得合规。

## 六、其它

- **日志落盘**：`~/.xml-agent/logs`，打包后的 exe 没有终端，这是唯一排查入口。
- **动作超时兜底**：内置动作按 `meta.timeoutMs` 统一超时，插件动作同理。
- **构建产物统一到 `release/`**：不再因绕文件锁而新建一堆 `release-build*` 目录，
  新增 `npm run release:clean`。
- **测试按需分组**：拆出 `test:api` / `test:desktop` / `test:live`，并加清单守卫，
  防止新增测试文件忘了挂进脚本。离线测试 53 个文件全绿。
- **工作区清单上限**：从"1200 条"改为"8k 字符"，大工作区不再撑爆首轮提示词。

## 七、升级说明

- 直接覆盖安装即可。工作区、会话、插件配置、API Key、技能都沿用原位置。
- 会话数据格式无变更，旧会话照常打开；上下文百分比会因为换成真实估算而与旧版显示不同，
  这是修正而不是回归。
- 插件开发者注意两条：`edit` 已成为内置动作保留名；`write` / `edit` 的内容校验现在共用一个
  检查器（`actions/content-check.js`），错误信息格式统一。
- **已知限制**：安装包 / 便携版自身的版本资源是 `1.3.0`，但解包后的 `XMLAgent.exe` 仍显示
  Electron 的 `33.2.0`。原因是本机 rcedit 写版本资源会报 `Unable to commit changes`
  （同一文件第二次写入必失败），构建脚本按既有约定跳过（`XML_AGENT_SKIP_RCEDIT=1`），
  只影响"属性 → 详细信息"里的显示，不影响功能。
