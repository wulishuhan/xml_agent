# Skills

给 Agent 用的"技能文件"：一份自包含的指令文档，模型按需 `read` 进来照着做。

对应 `docs/PLUGIN_DESIGN.md` 里的**技能文件模式**——插件文档太长会把系统提示词撑爆，
所以只往提示词里注入一行摘要 + `<read path=".agent/skills/xxx.md"/>`，细节由模型自己按需读取。

## 用法

1. 打开 WebUI（或桌面端）右上角的 **Skills** 面板
2. 左侧选一个技能，右侧直接读它的完整文档
3. 内置 / 用户级技能点 **Install to workspace** 复制进当前工作区，模型才读得到
4. 关掉面板，在任务里正常描述目标即可 —— 提示词会自动带上工作区里可用技能的清单

也可以完全手动：把技能文档放进 `<workspace>/.agent/skills/`（`.agent` 已在 .gitignore 里）。

## 三个来源（优先级从低到高）

| 来源      | 位置                                  | 说明               |
| --------- | ------------------------------------- | ------------------ |
| builtin   | `<安装目录>/skills/<name>/SKILL.md`   | 随仓库与安装包分发 |
| user      | `~/.xml-agent/skills/<name>.md`       | 跨工作区共享       |
| workspace | `<workspace>/.agent/skills/<name>.md` | 随项目走，可改可删 |

同名技能后一个覆盖前一个，被覆盖的那份在面板里标 `overridden`。
启用/禁用状态写在 `~/.xml-agent/skills.json`，只影响提示词，不动文件。

## 提示词里长什么样

只有"落在当前工作区内、且没被禁用"的技能会进首轮提示词（模型只读得到工作区里的文件）：

```
============================================================
可用技能（Skill）
============================================================

- 男频网文写作
  路径：.agent/skills/novel-writing.md
  用途：写小说、写网文、连续多章正文时按本文件执行
```

## 为什么不做成插件

插件要注册 action，会往模型的可用动作表里塞东西，而写作技能不产生新动作——
它约束的是"怎么写"，不是"能做什么"。用技能文件即可，模型少学一个动作，提示词也短。
